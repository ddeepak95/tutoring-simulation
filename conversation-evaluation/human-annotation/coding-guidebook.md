# Instructional item labeling guide

Label tutor sections using the items below. Student turns supply context only. Categories are fixed metadata; annotators select items. Each section can have several different items. Save one annotation per section/item pair with an occurrence count from 1 to 1,000 (default 1). Count repeated occurrences within the section; do not merge entries across sections. Evidence is the complete canonical source section, including its heading. Speaker labels and capture metadata are excluded.

Existing annotations use their pinned historical rubric. See coding-guidebook-legacy.md for the retired descriptive-label guide. Rating tasks continue to use rating-questions.md unchanged.

## Persistent section references

Portal sections have permanent IDs within their conversation: `t1s1` is the first section of the first tutor turn, `t1s2` its next section, and `t2s1` the first section of the second tutor turn. Register boundaries once and reuse them across annotators, item labels, LLM baselines, and exports. Resolve an ID using `(conversation_id, section_id)`; an ID alone is not globally unique. The section registry stores canonical turn IDs, UTF-16 source offsets, exact quotations, and a source fingerprint. Labels store `section_id`, item, category, and count; section evidence is resolved when reading. Existing IDs must never be renumbered or assigned new text. Revised conversation content needs a new conversation record.
